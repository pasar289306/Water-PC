# AquaAudit – پلتفرم ممیزی و مدیریت آب صنایع (نسخه MVP)

نرم‌افزار وب فارسی (RTL) برای ثبت جریان‌های آب یک مجتمع صنعتی، محاسبه موازنه آب با عدم قطعیت، شاخص‌های عملکرد (KPI)،
مدل‌های تجهیزات، بانک راهکارهای صرفه‌جویی، تحلیل اقتصادی پروژه‌ها و تولید گزارش ممیزی.
پیاده‌سازی بخش‌های «MVP» سند Methodology است (بدون هوش مصنوعی و بدون اتصال مستقیم به SCADA).

## نصب

نیازمند Python 3.11 یا بالاتر و دسترسی به اینترنت برای نصب وابستگی‌ها (pip).

**لینوکس / مک**
```bash
git clone https://github.com/pasar289306/Water-PC.git && cd Water-PC
./install.sh --run          # نصب و اجرا؛ گزینه --no-demo برای استقرار واقعی بدون داده نمونه
# بعداً:  ./start.sh
```

**ویندوز (PowerShell)**
```powershell
git clone https://github.com/pasar289306/Water-PC.git; cd Water-PC
powershell -ExecutionPolicy Bypass -File install.ps1 -Run
# بعداً:  powershell -ExecutionPolicy Bypass -File start.ps1
```

نصب‌کننده محیط مجازی `.venv` می‌سازد، وابستگی‌ها را نصب می‌کند و فایل `.env` را با `AQUA_SECRET` و گذرواژه
تصادفی مدیر (`AQUA_ADMIN_PASSWORD`) تولید می‌کند (فایل `.env` در git ذخیره نمی‌شود). سپس به
`http://127.0.0.1:8000` بروید و با کاربر `admin` وارد شوید.

> اسکریپت لینوکس/مک روی یک کپی تمیز آزمایش شده است؛ `install.ps1` در محیط ساخت (بدون ویندوز) اجرا نشده و
> در اولین استفاده روی ویندوز باید بررسی شود.

## نصب‌کننده ویندوز (.exe)

با هر push روی `main` (یا اجرای دستی) workflow «Build Windows installer» در GitHub Actions اجرا می‌شود،
تست‌ها را می‌گذراند، برنامه را با PyInstaller می‌سازد، نصب‌کننده Inno Setup را تولید می‌کند و هم `exe` و هم
نسخه نصب‌شده را تست دودی (smoke) می‌کند. خروجی‌ها:

- **Actions → آخرین اجرا → Artifacts → AquaAudit-Windows**: شامل `AquaAudit-Setup-<نسخه>.exe` (نصب‌کننده) و `AquaAudit-Portable-<نسخه>.zip` (بدون نصب).
- با ساخت تگ `v0.1.0` و push آن، همین فایل‌ها به **Releases** هم پیوست می‌شوند.

نصب برای کاربر جاری انجام می‌شود (بدون نیاز به دسترسی مدیر). هنگام اجرا، پنجره کوچکی با آدرس برنامه و گذرواژه اولیه
مدیر نمایش داده می‌شود و مرورگر باز می‌شود. داده‌ها در `%LOCALAPPDATA%\AquaAudit` ذخیره می‌شوند و با حذف برنامه پاک نمی‌شوند.

> فایل امضا نشده است؛ ویندوز (SmartScreen) ممکن است هشدار «Unknown publisher» بدهد: «More info → Run anyway».
> بسته نمونه دارای داده فرضی است؛ برای داده واقعی متغیر محیطی `AQUA_DEMO=0` را قبل از اولین اجرا تنظیم کنید.

## اجرای سریع (بدون install)

```bash
./run.sh                 # ساخت venv، نصب وابستگی‌ها و اجرا روی http://127.0.0.1:8000
```

یا با Docker:

```bash
export AQUA_ADMIN_PASSWORD='یک-گذرواژه-قوی'
export AQUA_SECRET="$(openssl rand -hex 32)"
docker compose up --build
```

- در اجرای محلی، گذرواژه اولیه کاربر `admin` (اگر `AQUA_ADMIN_PASSWORD` تنظیم نشده باشد) به‌صورت تصادفی ساخته و در
  `data/INITIAL_ADMIN_PASSWORD.txt` ذخیره می‌شود. پس از ورود آن را تغییر دهید و فایل را حذف کنید.
- به‌طور پیش‌فرض یک «مجتمع نمونه (داده فرضی)» با ۱۲ ماه داده مصنوعی ساخته می‌شود تا نرم‌افزار قابل بررسی باشد.
  برای استقرار واقعی `AQUA_DEMO=0` بگذارید. **داده نمونه کاملاً فرضی است.**

متغیرهای محیطی: `AQUA_DATA_DIR`، `AQUA_DB`، `AQUA_SECRET`، `AQUA_ADMIN_PASSWORD`، `AQUA_DEMO`.

## امکانات

| بخش | توضیح |
|---|---|
| موازنه آب | ΣQin − ΣQout − ΔS = R با عدم قطعیت u_R=√Σu_i² و Z=R/u_R؛ باقیمانده خودکار «نشتی» فرض نمی‌شود؛ جریان بازچرخانی داخلی دوبار شمرده نمی‌شود؛ داده invalid/missing کنار گذاشته و هشدار داده می‌شود |
| KPI | ۱۰ شاخص پیش‌فرض + تعریف شاخص جدید با فرمول (ارزیاب امن AST، بدون `eval`) و حدود هشدار/بحرانی |
| تجهیزات | برج خنک‌کن (E, B, D, M, COC)، صرفه‌جویی افزایش COC، بویلر/کندانس، RO، پمپ، تصفیه‌خانه |
| خط مبنا | رگرسیون چندمتغیره (تولید، دما، ساعات) + صرفه‌جویی تعدیل‌شده با عدم قطعیت و R²/CV(RMSE) |
| ناهنجاری | تشخیص آماری Z-score بر مصرف ماهانه (هشدار، نه اثبات نشتی) |
| بانک راهکارها | ۳۸ راهکار ساختاریافته (مبنای درصد، داده لازم، محدودیت کیفی، روش صحه‌گذاری) + پیشنهاد قاعده‌محور برای هر مجتمع |
| اقتصاد | هزینه واقعی هر m³، بازگشت سرمایه، NPV، IRR، هزینه چرخه عمر، رتبه‌بندی وزنی |
| ورود داده | فرم، CSV (UTF-8/Windows-1256، گزارش خطا به‌تفکیک خط)، سابقه منبع داده |
| امنیت | JWT، گذرواژه PBKDF2، نقش‌ها (مدیر/مهندس/مشاهده‌گر)، لاگ فعالیت، فرار HTML در UI و گزارش |
| گزارش | گزارش HTML قابل چاپ/ذخیره PDF |

## تعاریف مهم (برای تفسیر درست KPIها)

- **مصرف واقعی (consumed)** = ورودی − پساب/بلودان تخلیه‌شده (برداشت، مصرف و تخلیه یکی نیستند).
- **مصرف ویژه آب (SWC)** = مصرف واقعی / تولید؛ **شدت برداشت (FWI)** = آب تازه / تولید.
- **نرخ بازچرخانی** = جریان‌های داخلی (scope=internal) / (ورودی + بازچرخانی).
- **راندمان مصرف** = (ورودی − نشتی − باقیمانده مثبت) / ورودی؛ تعریف «مفید» را متناسب با صنعت بازبینی کنید.
- آستانه ۱۰٪ موازنه فقط **آستانه غربالگری** است (قابل تنظیم برای هر مجتمع).

## محدودیت‌ها و نکات صادقانه

1. **پشته فنی:** در محیط ساخت، نصب FastAPI/SQLAlchemy ممکن نبود؛ بک‌اند با Starlette + sqlite3 ساخته شد. ساختار API و
   جداول با طرح سند سازگار است و انتقال به FastAPI/PostgreSQL مستقیم است. sqlite برای یک سایت و چند کاربر مناسب است؛
   برای چندکارخانه‌ای/همزمانی بالا به PostgreSQL مهاجرت کنید.
2. **اعتبارسنجی مهندسی:** فرمول‌ها با تست‌های مرجع محاسبه‌شده دستی کنترل شده‌اند، اما بانک راهکارها (بازه‌های صرفه‌جویی،
   بازگشت سرمایه) و فرمول تبخیر برج (قاعده سرانگشتی 0.00085×1.8×ΔT×Q) **باید توسط متخصص آب/فرآیند** هر صنعت بازبینی
   و با داده سایت راستی‌آزمایی شوند؛ هیچ عددی ادعای تضمین ندارد.
3. **خارج از دامنه این نسخه:** مدل‌های هوش مصنوعی (پیش‌بینی، خرابی)، Water Pinch/MILP، اتصال PLC/SCADA/OPC UA،
   TimescaleDB، موازنه سطح فرآیند/تجهیز به‌صورت خودکار (موازنه فعلی در سطح سایت است)، API کنترلی. این‌ها فازهای بعدی نقشه راه‌اند.
4. **امنیت استقرار:** پشت HTTPS (reverse proxy) اجرا کنید، `AQUA_SECRET` ثابت و قوی بگذارید، از `data/` پشتیبان بگیرید.
   محدودسازی نرخ تلاش ورود پیاده‌سازی نشده است (در لایه proxy اعمال کنید).
5. فایل Docker در محیط ساخت (بدون Docker) اجرا نشد؛ اجرای محلی (`run.sh`/uvicorn) و تست مرورگر انجام شده است.


## کاتالوگ صنایع و سیستم‌های مصرف‌کننده آب (نسخه 0.2)

بخش ۱ و ۲ سند Methodology به‌صورت کامل در نرم‌افزار آمده است (منوی «طبقه‌بندی صنایع و سیستم‌ها»):

- **۱۵ صنعت** (IND-01..15) با زیرگروه، سیستم‌های نوعی، فرآیندها و راهکارهای شاخص؛ انتخاب صنعت/زیرگروه هنگام تعریف مجتمع و «اعمال الگوی صنعت».
- **۱۲ سیستم مصرف‌کننده** (SYS-01..12) با تجهیزات، جریان‌های نوعی ورودی/خروجی، اندازه‌گیری‌ها، شاخص‌ها، **فرمول‌ها** و ماژول محاسباتی.
- **انواع جریان** (۱۷ نوع با مبدأ، مقصد، کیفیت، کاربرد مجاز و وضعیت بازیافت) و **۵ دسته منبع تأمین**.
- **بانک تجهیزات** (بیش از ۱۵۰ نوع؛ ردیف‌های «سند» از جدول سند و «راهنما» تکمیلی و نیازمند بازبینی متخصص) و تجهیز مجتمع از همین بانک انتخاب می‌شود.
- **بانک پارامترها (۲۳) و تجهیزات اندازه‌گیری (۷)**.
- گزارش مصرف به تفکیک سیستم (`/api/sites/{id}/by-system`) و پیشنهاد راهکار بر پایه سیستم‌ها/صنعت.
- ماشین‌حساب‌های جدید: DM، شبکه توزیع/آتش‌نشانی، مصارف بهداشتی، آبیاری.
- مهندس می‌تواند صنعت، سیستم، نوع جریان و نوع تجهیز بیفزاید/ویرایش کند؛ ردیف‌های کاربر با بروزرسانی نرم‌افزار بازنویسی نمی‌شوند.
- نسخه قبلی کاملاً سازگار است: دیتابیس‌های قدیمی خودکار مهاجرت می‌شوند (تگ `v0.1.0` = نسخه قبلی).

## تغییرات نسخه‌ی رابط و اقتصاد
- داشبورد مجتمع صنعتی: نمودار سنکی، مصرف به تفکیک سیستم، شاخص‌های مصرف/عملکرد و چکیده کارایی اقتصادی راهکارهای منتخب.
- «ساختار سیستم آب مجتمع» (جایگزین «ساختار و جریان‌ها») با زیرصفحه‌ی طبقه‌بندی صنایع و سیستم‌های مصرف‌کننده آب.
- «پروژه‌ها و اولویت‌بندی»: انتخاب راهکارهای منتخب، ارزیابی تجمیعی، و ماژول تحلیل اقتصادی (بازگشت ساده و تنزیل‌یافته، NPV، IRR، BCR، جدول جریان نقدی).
- بررسی یکپارچگی ارجاع‌ها: `GET /api/integrity` و `GET /api/sites/{id}/integrity` (کارت «بررسی یکپارچگی داده‌ها» در داشبورد).

## ورود داده‌های سری زمانی (نسخه 0.3)
- **بازه و تقویم دلخواه:** هر مقدار با تاریخ شروع و پایان دقیق (میلادی یا شمسی، به انتخاب کاربر) ثبت می‌شود؛ دانه‌بندی سالانه، ماهانه، روزانه یا بازه‌ی دلخواه. تاریخ‌ها در پایگاه داده به‌صورت میلادی ذخیره و در رابط به تقویم انتخابی نمایش داده می‌شوند. تقویم گزارش‌گیری هر مجتمع (میلادی/شمسی) در فرم مجتمع تعیین می‌شود؛ مقادیر سالانه/بازه‌ای به‌نسبت روز به ماه‌های گزارش تسهیم می‌شوند.
- **چهار روش ورود:** (۱) ثبت دستی با جدول دوره‌ها و چسباندن از Excel؛ (۲) بارگذاری Excel/CSV (قالب عریض و بلند، قالب نمونه قابل دانلود)؛ (۳) API با کلید (`POST /api/ingest/v1/entries`, `/meter-reads`, `GET /ping`؛ هدر `X-API-Key`)؛ (۴) اتصال مستقیم به کنتور (Modbus TCP یا HTTP/JSON، تجمعی یا لحظه‌ای) با پایش پس‌زمینه.
- **چند کنتور برای هر منبع:** هر جریان آب (چاه، شبکه شهری، تانکر، باران، پساب بازیافتی…) می‌تواند چند کنتور داشته باشد؛ حجم = مجموع کنتورها و عدم‌قطعیت مؤثر از ترکیب خطای کنتورها؛ جدول خلاصه‌ی تعداد کنتور بر حسب نوع منبع.
- **متغیرهای سری زمانی:** حجم جریان، تولید، ساعات کارکرد، دما، تغییر موجودی، انرژی، بارش، ET0، تعداد افراد، پارامترهای کیفی و متغیرهای تعریفی کاربر؛ با نوع تجمیع (جمع/میانگین) و جدول پوشش داده و هشدار شکاف.
- قواعد هم‌پوشانی: ثبت یکسان = به‌روزرسانی؛ هم‌پوشانی غیریکسان رد می‌شود مگر با گزینه‌ی «جایگزینی».
- پیکربندی اتصال مستقیم کنتور فقط برای مدیر است. اتصال Modbus/HTTP فقط با شبیه‌ساز آزموده شده؛ پیش از بهره‌برداری با کنتور واقعی بیازمایید.
- متغیر محیطی `AQUA_NO_POLLER=1` پایش پس‌زمینه کنتورها را خاموش می‌کند.

## ورود داده‌های سری زمانی (Time-series ingestion)

- **بازه و دقت:** سالانه، ماهانه، روزانه یا بازهٔ دلخواه؛ تاریخ میلادی یا شمسی (تقویم گزارش‌دهی هر مجتمع در فرم مجتمع قابل تنظیم است).
- **چهار روش ورود:** ثبت دستی (جدول/چسباندن از اکسل)، بارگذاری Excel/CSV (قالب قابل دانلود)، API (کلید API هر مجتمع)، اتصال مستقیم به کنتور (Modbus TCP یا HTTP/JSON، تجمعی یا لحظه‌ای).
- **چند کنتور برای هر منبع:** هر جریان آب می‌تواند چند کنتور داشته باشد؛ جمع‌بندی بر حسب نوع منبع در صفحهٔ کنتورها.
- **متغیرها:** تولید، جریان‌های آب، ساعت کار، دما، انرژی، بارش، پارامترهای کیفی و متغیرهای دلخواه همگی سری زمانی‌اند.
- **API:** `POST /api/ingest/v1/entries` و `/api/ingest/v1/meter-reads` با هدر `Authorization: Bearer <key>`؛ `GET /api/ingest/v1/ping`.
- برای غیرفعال‌کردن نظرسنجی کنتورها: `AQUA_NO_POLLER=1`.
